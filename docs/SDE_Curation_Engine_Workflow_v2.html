Status Machine (6 States)

Backlog➜ Scraped➜ Curating➜ Curated➜ Config Gen.➜ Live
Curating sub-stages: exclusions → metadata
needs_recuration set only by re-crawl or SME — never by an index failure
Every transition written to status_history + audit_log

Cross-Cutting Principles

  • Recompute stays whole (no pagination) but carries no page text
  • Text paths stream: ingest, LLM (keyset 200), export (pages of 500)
  • Pure engine (patterns, diff, urls): unapply = delete rule + recompute
  • Every job records explicit failure; scrape + AI metadata resume after a restart
  • One job per collection; one engine task (in-process registry + SSE)
  • Blank metadata is never promoted; AI fills every field

Progress via SSE; Slack-compatible webhook on each status transition

Key Outputs / Artifacts

  • DumpUrl + page_text: crawl, one text per hash
  • DeltaUrl: new / modified / deleted + AI suggestions
  • CuratedUrl: approved set + content hash
  • documents.jsonl + manifest.json (WEB_COSMOS)
  • index_runs: test/prod validation results
  • status_history + audit_log (append-only)

Verification

  • pytest on real Postgres (Docker), driven through API flows, not DB shortcuts
  • Rule semantics, diff, promote, duplicates, blank metadata, scale (100K URLs)
  • e2e: seed collection through all 6 stages against test AOSS (docs/e2e-test.md)

Runtime

  • CloudFront + WAF → ALB → one ECS task (FastAPI + HTMX + SSE)
  • psycopg pool (16); migrations at boot; per-user logins (admin / curator)
  • Infra as CDK (infra/stacks/engine_stack.py)

Dropped (Out of Scope)

  • TDAMM tagging, feedback app, EJ app, dashboards, backup tooling
  • 20-state workflow / 7-state reindexing machine
  • Tombstones in prod; SQLite/Parquet state store (now RDS)
