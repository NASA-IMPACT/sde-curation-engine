What it is

The engine takes a website from a seed URL to a live entry in the SDE search index. It runs the crawler and the WEB_COSMOS indexer for you and gives you one place to decide what gets indexed and how each page is described. Every collection moves through the same six stages, and the app always shows you the one next thing to do.

Backlogadded, not crawled
Scrapedcrawl loaded
Curatingexclusions → metadata
Curatedapproved set promoted
Test indexindexed, validated
Livein the prod index

Statuses only move forward when the data supports it. A failed validation, or a re-crawl after promotion, sends the collection back to Curating with a ⚠ needs re-curation flag.

Three ideas carry the whole app:

  • Three URL sets, always called the same thing. Dump URLs is what the crawler found, raw. Delta URLs is what will change in the curated URLs when you promote. Curated URLs is the approved set; its included rows go to the index. You never edit dump pages. You decide what to do with them.
  • Everything is a rule. Excluding a URL, fixing a title, picking a division: each is a rule you can see, filter by, and delete. Even a one-off edit on a single row is a rule that matches exactly that URL. Rules belong to the collection they were made in; nothing you accept here touches another collection. The only shared input is the global exclude list, and it only ever suggests.
  • Delta URLs are computed, not typed. The engine diffs the dump URLs against the curated URLs and applies your rules. You review the result and promote it.

The quick path

If you only read one section, read this one. Every collection goes through these clicks in this order. The blue Next button in the header always points at the current one.

From seed URL to live index
  1. Add collection on the dashboard: seed URL, name, division, max pages.
  2. Scrape, or load existing if the crawler already has output.
  3. Start curating to compute the delta URLs.
  4. Suggest exclusions, then accept or reject every suggestion.
  5. Continue to metadata.
  6. Suggest metadata, then accept all titles, divisions, and types, or review one by one.
  7. Promote the delta URLs into the curated URLs.
  8. Index to test and wait for validation to pass.
  9. Index to prod. The collection is Live.

Signing in: deployed environments require a login. Admins add accounts at /users, everyone changes their own password at /account. Curators can do everything except manage users and delete collections. Every action is recorded under your name.

Walkthrough with screens

The same path, one screen at a time, with what to look at on each.

  1. Find or add the collection on the dashboard

    The home page lists every collection with its status, the dump / delta / curated URL counts, its last job, and the one button for the next step. The filter pane narrows by status, the curating sub-stage, the needs re-curation flag, division, and curator. Press / to jump to search. The jobs strip above the table shows everything running anywhere.

    To add a site, fill in the seed URL, a display name, the division, and a page cap, then press Add collection. The collection id is derived from the seed host.

  2. Scrape the site, or load a crawl that already exists

    Open the collection and press Scrape. The header shows a spinner and live document counts, with a cancel button next to it. When the crawler already has output for this site, the header also offers or load existing with the date of that output. That ingests it without re-crawling.

    On the deployed environment the crawler is a shared machine that runs one crawl at a time. If someone else's crawl is running, yours shows as queued with how many crawls are ahead. A queued job has no timeout and can legitimately wait a long time.

    When it finishes, the Overview tab's step panel says how many pages were crawled and how many failed, and the Next button becomes Start curating.

  3. Exclusions: decide what must never be indexed

    Press Start curating. The engine computes the delta URLs and opens the Curate tab at section 1. Press ✨ Suggest exclusions. It first applies the team's global exclude list, then sends the included delta URLs and titles to the model in batches and asks for exclude globs. On a first pass that is the whole dump; after a re-crawl only what changed, so 90 delta URLs on a 100k-page site cost one call. The button tells you how many URLs and how many calls before you press it; it stays disabled until you have started curating.

    Every suggestion has three options. Accept creates a real exclude rule and recomputes the delta URLs. Edit turns the glob into a text box so you can narrow or widen it (say */tag/* to */blog/tag/*) and then Save & accept: the rule is created with your glob and recorded as AI, edited. Reject dismisses it. You can also add an exclude or include rule by hand: a glob with *, or an exact URL. When every suggestion is decided, press Continue to metadata.

    Know this

    Re-running Suggest exclusions replaces any suggestions you have not yet decided.

    The Metadata section is locked until every exclusion suggestion is decided. If you skipped Suggest exclusions entirely, metadata is allowed with a hint.

  4. Metadata: titles, divisions, and document types

    Press ✨ Suggest metadata. It makes one model call per included delta URL that has not been classified yet, sending the full page text. Each answer carries a title, a division, and a document type, each with a confidence: high means explicit in the text, medium a strong inference, low a guess. Answers are saved as they arrive, so cancelling keeps what finished.

    To see the suggestions on the rows themselves, press Review one by one or open URLs › Delta URLs. Each AI badge shows the proposed value and its confidence, with ✓ to accept, ✎ to edit it first (the title opens in an editor prefilled with the suggestion; for division and type the dropdown jumps to the suggested value so you can pick another), and ✕ to dismiss. A value you change before accepting is recorded as AI, edited. Filter the table by confidence to review only the medium and low ones by hand and accept the rest in bulk.

    Why the Rules count jumps

    Accepting 22 titles, 22 divisions, and 22 types adds 66 rules, one exact-URL rule per accepted value. That is expected. It is what makes every accepted value visible and reversible in the rules table. Exclude suggestions are globs and stay few.

  5. Promote the delta URLs

    Section 3 of the Curate tab. Promote writes the delta URLs into the curated URLs and marks the collection Curated. If there are no delta URLs, the button reads Mark curated. Recompute delta URLs re-applies the rules without promoting, useful after hand-editing several rules.

    Know this

    Promoting discards any AI suggestions still undecided. The Promote section warns you with the count. Accept or reject them first.

  6. Index to test, validate, then index to prod

    Index to test exports the included curated rows and dispatches an indexing run against the test index. The step-5 panel shows exported, indexed, changed, and deleted counts as it progresses, then the validation result.

    The engine validates on its own. About thirty seconds after the run succeeds it queries the index directly for this collection and compares counts and titles against the curated URLs. If it lacks access to query the index, it dispatches a second pass of the same export purely to get a fresh validation file. Nothing is re-vectorised on that pass.

    Pass
    Counts match and at least 99% of titles match. Status becomes Test index and Index to prod is enabled.
    Fail
    Back to Curating with the needs re-curation flag and the mismatches listed. Fix and re-index, or press Re-validate if you believe the index only needed more time.

    Index to prod is refused until the latest test run passed. Success marks the collection Live and clears the flag. Every status transition posts to the team Slack channel with a link.

Screens reference

The workbench header

Sticky on every tab. Name, seed link, status badge, the running job with a cancel button, and four count chips that are also links:

Dump URLs
Every URL the last crawl found. Raw, but you can exclude or include a row right there.
Delta URLs
What will change in the curated URLs when you promote: new · modified · removed · excluded.
Curated URLs
The approved set: metadata plus the page text each row was approved with. Included rows, with that text, are what gets exported to the index. Every field is still editable; an edit becomes a delta URL.
Rules
Every rule in force for this collection, including exact-URL rules from per-row edits and accepted AI suggestions, each with its source (AI, AI edited, SME, global list).

The four tabs

Overview
The clickable pipeline with a panel per step, details, the last job, and Advanced (Re-scrape, manual status override, Delete for admins).
Curate
Exclusions, Metadata, Promote, in the order you work them, with the full rules table underneath.
URLs
Three sets: Dump URLs, Delta URLs, Curated URLs. Search, filter by change kind, exclusion, division, type, AI confidence, and text changed. Download the filtered rows as CSV.
Activity
Every job, the status history, and the audit trail.

The Jobs page

/jobs lists every running or queued job across all collections, who started it, and live progress, with the recent history underneath. The dashboard carries a compact version of the same strip.

How rules resolve

Every URL's effective title, division, document type, and included or excluded state is computed from the rules of its own collection; a rule never reaches another collection. When several rules match the same URL:

  • The most specific rule wins. Specific means the rule with the smallest number of matching URLs. On a tie, the longer pattern string wins. An exact-URL rule matches one URL, so it is always the most specific.
  • Include always beats exclude, regardless of specificity. Use include rules to carve exceptions out of broad excludes.
  • No rule, then the curated value, then nothing. Deleting a rule falls back to the next most specific rule, then to whatever was last promoted, then to blank. Deleting is the undo.

Title rules are templates. {title} is the scraped title, {url} the URL, {collection} the collection name. A rule with value {title} | GES DISC appends a suffix to every matching page.

Hover any field on the Delta, Curated or Dump URLs to see which rule set it, and who made that rule. The Edited by column summarises it per row: a row whose values all come from accepted AI suggestions reads AI; one you typed or toggled reads SME; both, AI + SME. A broad rule you typed (say a * title template) marks every row it wins as SME, which is correct: you decided it. Match counts in the rules table link to the matching rows.

Know this

A URL excluded by a rule never reaches the export, the index, or the metadata model. Exclude early to save model calls and review time.

Jobs

  • One job per collection at a time. While a job runs, every button that would change that collection is disabled, and any direct request is refused with a conflict. Cancel first if you need to act now.
  • Progress is live. The header chip, the Curate tab, the dashboard row, and the jobs strip show the same progress text and update within seconds.
  • Cancel is safe. A cancelled metadata job keeps every answer that had already arrived. A cancelled scrape leaves the previous crawl in place.
  • Every job ends in succeeded or failed with a reason, shown on the header, the Overview panel, and the Activity tab. Nothing fails silently.
  • An engine restart fails running jobs with the message "engine restarted while job was running". Start them again.

Working alongside others

Concurrency is per collection, not global. Any number of collections can have jobs running at once. Within one collection, exactly one job runs and edits wait their turn.

  • Different collections never block each other. Assign people to distinct collections and everything is safe.
  • Scrapes queue on the shared crawler. Several people can press Scrape at once. The crawls run one after another. Kick them off early.
  • LLM jobs run in parallel with no shared cap. Each metadata job runs its own pool of concurrent model calls, default twenty-four. Five people classifying at once is over a hundred calls in flight and will hit the provider's rate limit first. Stagger large runs.
  • Job activity is pushed to everyone's browser. You see a colleague's job start and finish live.
  • Edits are not pushed. Header counts catch up within ten seconds, but the URL table and rules list only reload when a job finishes or you refresh. If two people edit the same row of the same collection, the last save wins and nobody is warned. The audit trail records who did what.

Things to know

The list people wish they had read first. Some repeat points from above, gathered in one place.

  • A re-scrape replaces the dump URLs and clears the delta URLs and, if anything was ever promoted, raises the needs re-curation flag. Your rules survive. Undecided suggestions do not.
  • When pages disappear from the crawl. Say the first crawl found 100 dump URLs and the next one 90. Start curating lists the 10 as removed delta URLs. Promote drops them from the curated URLs, and the next index run deletes them from the index. That is the right outcome for pages a site took down. It is the wrong outcome for a crawl that stopped early, so Promote warns you when a large share of the curated URLs vanished at once: re-scrape instead. To keep a page out of the index while it is still on the site, exclude it; that is the "delete from the index" action.
  • An identical re-crawl returns straight to Curated. Recompute never demotes a collection when nothing changed.
  • Modified includes "text changed". Each page carries a hash of its text. A page whose title and metadata did not move but whose body did shows as modified with a text changed badge, and Suggest metadata re-classifies it. Pages promoted before this existed compare as unchanged the first time.
  • The curated URLs keep their text. Promote copies each page's text from the dump onto its curated row, next to the hash, and an index run ships the curated rows alone. A later re-scrape replaces the dump but not what was approved, so the curated URLs are the source of truth for the next cycle. The Text column on the Curated URLs table is the size of that text; a dash means the row was promoted before the engine kept it, and the next promote fills it.
  • Max pages caps the crawl. If the Dump URLs count sits exactly at the cap, the site is bigger than the crawl. Raise the cap and re-scrape.
  • The Curator filter means who created the collection, not who is working on it. There is no assignment field.
  • The manual status override still obeys the data. Advanced › Set status will not put a collection in Scraped without a crawl, or in Curated with delta URLs outstanding.
  • Suggest exclusions sees URLs and titles only. It cannot know what a page says. Suggest metadata reads the whole page and never truncates it. A page beyond the model's window fails that single URL, is counted, and is retried on the next run.
  • The prompts are inspectable. Both suggestion cards have a "Show the prompt" toggle. If suggestions look off, read what the model was asked.
  • A malformed model reply fails the job and writes nothing. A bad API key or model name aborts after ten consecutive errors. Per-URL failures never abort.
  • Validation waits on purpose. The thirty-second pause after a test run is the index refresh window, not a stall.
  • Prod indexing is gated on the latest test run. A new test run after a passed one resets the gate until it passes too.
  • CSV export follows your filters. The download on the URLs tab contains exactly the rows you are looking at.
  • Old links still work. Links to the previous curate page, and set=deltas links, redirect into URLs › Delta URLs.
  • Delete is admin only and permanent. It removes the collection, its crawl, its rules, and its history from the engine. Crawler output in S3 is untouched.
